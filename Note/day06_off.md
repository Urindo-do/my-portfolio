## 1. AI 코딩 환경 구축

### AI 코딩 IDE의 기반
- VS Code는 **오픈소스**이고 잘 만들어져 있어서, 이를 복사·확장해서 만든 AI 코딩 도구들이 많다.
  - 예: Cursor, Antigravity 등
- 이런 도구들은 VS Code를 기반으로 AI 기능을 얹은 형태다.

### GitHub Copilot — AI 코딩 비서
- **에디터 내장의 강점**이 크다. 별도 창을 오가지 않고 코드 작성 흐름 안에서 바로 도움을 받을 수 있다.
- 주요 기능:
  - **지능형 자동완성** — 다음에 올 코드를 예측해서 제안
  - **맥락 인식 사이드바 챗** (`Ctrl+Shift+A`) — 현재 코드 맥락을 이해한 채로 대화

### 에러 해결 워크플로우
- 에러가 생기면 **하나씩** 해결해 나가는 습관이 중요하다.
- **웹페이지(HTML)**: 에러가 화면에 안 보일 수 있음 → `F12`(개발자 도구)로 확인
- **파이썬(Python)**: 에러 메시지를 그대로 복사해서 AI에게 붙여넣어 해결

## 2. ESP32-S3 & 아두이노 IDE 설치

### 왜 ESP32인가
- 이번 과정에서는 **ESP32-S3** 보드를 사용한다.
- 특징:
  - **통신 기능**이 강력하다 (WiFi, Bluetooth 내장)
  - 키보드·마우스 입력을 흉내내서 PC에 인식시키는 것도 가능하다
  - 일반 아두이노보다 **핀이 더 많아** 더 많은 부품을 연결할 수 있다

### 코딩 툴
- 기본 도구: **아두이노 IDE** (VS Code로도 가능)
- 아두이노 IDE에서 **보드 매니저(Boards Manager)**와 **라이브러리 매니저(Library Manager)**를 주로 사용한다.

### ⚠️ 버전 호환성 — 중요 포인트
- ESP32 코어는 **2.0.17 버전**으로 고정해서 설치했다.
- 이유: 최신 버전(3.x)으로 올리면 **호환성 문제**가 발생한다.
  - 2.0.17은 ESP-IDF 4.4 기반, 3.x는 ESP-IDF 5.1 기반으로 핵심 API 구조가 바뀌었기 때문 (breaking change).
  - 부트캠프 교재·예제가 2.x 기준으로 작성되어 있어 최신 버전에서는 오히려 자료를 못 따라간다.
- **버전까지 지정해서 설치**하는 것이 하드웨어 실습에서 특히 중요하다.

> 💡 **하드웨어 vs 소프트웨어 개념 정리**
> - 아두이노는 **5V**를 사용한다.
> - ESP32는 **3.3V**를 사용한다.

## 3. USB 드라이버 설치

ESP32와 PC가 통신하려면 **USB 시리얼 드라이버**가 설치되어야 한다.

| 드라이버 | 용도 |
|---|---|
| CP210x | Silicon Labs 계열 USB-Serial 칩용 |
| **CH340** | 이번에 설치한 드라이버 (WCH 계열) |

- 다운로드: https://www.wch-ic.com/downloads/CH341SER_EXE.html
- 드라이버 없이도 연결될 수 있지만, **안정적인 인식을 위해** 설치한다.
- 설치 확인: 장치 관리자 → 포트(COM & LPT) → `USB-SERIAL CH340 (COMx)` 표시되면 정상

## 4. 보드 & 포트 설정

아두이노 IDE의 **Select Other Board and Port**에서:
- 보드: **ESP32S3 Dev Module**
- 포트: **COM3**로 잡음 (환경에 따라 번호 다름)

### COM이란?
- **COM = Communication Port**의 약자
- 과거 시리얼 포트(RS-232) 시절부터 이어진 이름으로, USB로 연결된 ESP32도 Windows 입장에서는 "가상 시리얼 포트"로 인식되어 COM 번호가 붙는다.
- ESP32 ↔ PC 통신 자체가 근본적으로 **시리얼 통신**이기 때문이다.

### Compile vs Upload
- **Compile(✓ 체크)**: 사람이 쓴 코드를 컴퓨터가 이해하는 기계어로 번역하는 과정
- **Upload(→)**: 컴파일된 코드를 실제 ESP32 보드로 밀어넣는 과정
- 코드를 수정한 뒤 Upload를 다시 하면 보드에 새 코드가 반영된다.

> ⚠️ **트러블슈팅 메모**: 업로드 시 `No serial data received` 에러가 나면
> → USB 재연결 또는 다른 COM 포트 시도 (COM3 → COM5로 바꿔 해결한 경험)
> → 그래도 안 되면 BOOT 버튼 누른 채 RESET 눌렀다 떼기 (수동 부트 모드)

## 5. 브레드보드 구조 이해

> 납땜 없이 전자회로를 구성하는 브레드보드의 **내부 연결 구조**를 알아야 배선 실수를 피할 수 있다.

### 핵심 연결 규칙

```
   1  2  3 ... 13 ... 20
a  ○  ○  ○     ○      ○     ┐
b  ○  ○  ○     ○      ○     ├─ 같은 번호(열)의 a~e는 세로로 연결
c  ○  ○  ○     ○      ○     │
d  ○  ○  ○     ○      ○     │
e  ○  ○  ○     ○      ○     ┘
   ▔▔▔▔ (중앙 홈 — 여기서 끊김) ▔▔▔▔
f  ○  ○  ○     ○      ○     ┐
g  ○  ○  ○     ○      ○     ├─ f~j는 별개의 그룹으로 세로 연결
h  ○  ○  ○     ○      ○     │
i  ○  ○  ○     ○      ○     │
j  ○  ○  ○     ○      ○     ┘
```

- **본체(a~j)**: 같은 번호 열에서 `a~e`가 하나의 그룹, `f~j`가 또 다른 그룹. 중앙 홈을 사이에 두고 **서로 분리**되어 있다.
- **전원 레일(맨 위/아래 +/- 줄)**: 가로로 길게 전체가 하나로 연결.
- **합선 주의**: 구조를 잘못 이해하면 저항을 건너뛰는 지름길이 생겨 부품 손상 위험. `+`와 `-` 배치를 잘 봐야 한다.

> 💡 오늘 가장 헷갈렸던 부분: `a~j`가 전부 연결된 줄 알았는데, 실제로는 `a~e` / `f~j`로 **나뉘어** 있었다. 같은 번호 열이라도 그룹이 다르면 다른 노드다.

## 6. 실습 ① 디지털 출력 (LED 제어)

### 디지털 출력이란?
컴퓨터가 특정 핀으로 **전기를 내보내거나(HIGH) 끊는(LOW)** 것.

### 배선 (GPIO13 → LED)
```
GPIO13 → 저항(220Ω) → LED(+, 긴 다리) → LED(-, 짧은 다리) → GND
```

### 코드
```cpp
const int LED_PIN = 13; // 13번 핀을 제어 핀으로 지정

void setup() {
  pinMode(LED_PIN, OUTPUT); // 출력 모드로 설정
}

void loop() {
  digitalWrite(LED_PIN, HIGH); // 전기 보내기 (LED 켜짐)
  delay(1000);
  digitalWrite(LED_PIN, LOW);  // 전기 끊기 (LED 꺼짐)
  delay(1000);
}
```

### 배운 점
- `digitalWrite(pin, HIGH)`는 **GPIO 핀 자체가 3.3V를 출력**하는 것. 별도 3V3 핀을 끌어올 필요 없이 GPIO 하나로 전원+제어를 동시에 한다.
- **GPIO vs 3V3 핀의 차이**:
  - GPIO: 신호용, 최대 약 40mA (LED 하나 정도는 충분)
  - 3V3: 전용 레귤레이터 출력, 더 큰 전류 공급 가능 (센서처럼 상시 전원이 필요한 부품용)
- ⚠️ 3V3은 **출력 전용**. 외부 전원을 넣고 싶으면 VIN/5V 핀으로 넣어야 하고, 3V3에 직접 넣으면 보드가 손상될 수 있다.

### (심화) 내장 RGB LED — neopixelWrite
```cpp
void setup() {
  pinMode(RGB_BUILTIN, OUTPUT);
}

void loop() {
  neopixelWrite(RGB_BUILTIN, 64, 64, 64); // 흰색
  delay(1000);
  neopixelWrite(RGB_BUILTIN, 0, 0, 0);    // 끄기
  delay(1000);
}
```
- `neopixelWrite`는 ESP32 코어가 제공하는 함수로, RMT 하드웨어로 네오픽셀 LED에 정밀한 타이밍 신호를 보낸다.
- (참고) 최신 코어에서는 `rgbLedWrite`로 대체되었다.

## 7. 실습 ② 디지털 입력과 플로팅 현상

이번에는 출력이 아니라 **입력**을 받아본다. LED는 빼고 **스위치 하나만** 관찰.
스위치는 ESP32와 겹치지 않는 영역에 연결한다.

### 플로팅(Floating) 현상 — 문제 재현
```cpp
const int BUTTON_PIN = 4;

void setup() {
  Serial.begin(115200);
  delay(1000);
  pinMode(BUTTON_PIN, INPUT); // 풀업 없이 → 핀이 공중에 뜬(Floating) 상태
}

void loop() {
  int buttonState = analogRead(BUTTON_PIN);
  Serial.print("Button State (INPUT mode): ");
  Serial.println(buttonState); // 안 눌러도 값이 불안정하게 흔들림
  delay(100);
}
```
- 아무것도 안 건드려도 값이 불규칙하게 흔들린다 = **플로팅**.
- 핀이 HIGH/LOW 중 무엇인지 결정해줄 게 없어 주변 전기 잡음에 따라 값이 떠다니는 것.

### 해결 — 내부 풀업 저항
```cpp
const int BUTTON_PIN = 4;

void setup() {
  Serial.begin(115200);
  delay(1000);
  pinMode(BUTTON_PIN, INPUT_PULLUP); // 핵심: 내부 풀업으로 핀을 3.3V에 안정 고정
}

void loop() {
  int buttonState = digitalRead(BUTTON_PIN);

  // Active LOW 구조: 누르면 LOW, 놓으면 HIGH
  if (buttonState == LOW) {
    Serial.println("0 (Pressed)");
  } else {
    Serial.println("1 (Released)");
  }
  delay(100);
}
```

### 배운 점
- `INPUT_PULLUP`은 칩 내부 저항으로 핀을 3.3V에 약하게 묶어, 평소엔 항상 HIGH로 안정화시킨다.
- **Active LOW 구조**: 버튼을 누르면 GND로 연결되어 LOW가 되고, 이때가 "눌린" 상태. 일반 직관(누르면 1)과 반대라 주의.

> ⚠️ **트러블슈팅 메모**: 코드 붙여넣기 후 `stray '\302'` 에러가 나면
> → NBSP(특수 공백)가 섞인 것. 코드를 지우고 직접 타이핑하거나 서식 없이 붙여넣기로 해결.
