## 1. 틴커캐드란?

- **Autodesk의 브라우저 기반 시뮬레이터** — 3D 모델링 + 물리 회로 시뮬레이션, 설치 불필요
- 부품을 드래그해서 배치·연결, **아두이노 UNO를 올리면 C++ 코드 작성/실행까지 가능**
- 잘못 연결하면 경고를 띄우고, 과전류로 부품이 "터지는" 상황도 시뮬레이션해줌
- **왜 쓰는가**: 실물에서는 배선 실수가 부품 파손·비용으로 직결됨. 게다가 부품이 죽어도 겉으로 티가 안 나는 경우가 많아서, "코드가 문제인 줄 알았는데 알고 보니 부품 사망"인 경우가 흔하다 → **사전 시뮬레이션 = 하드웨어 버전의 테스트 검증**

수업 참고 사례 (ESP32 활용 글로벌 메이커 프로젝트):
- ESP32 잠수함 (WiFi 대시보드, 주사기+기어 부력 조절, 서보 방향 제어)
- 전력 소비 모니터링 웹페이지 (OLED 디스플레이)
- 위성 데이터 수신 구름 디스플레이
- 풍향/풍속 측정기 (PCB 설계, strain gauge)
- 영상: https://www.youtube.com/watch?v=M0FKp2y9JoA

## 2. 기초 회로 — 코드 없는 물리 제어

### 2-1. LED + 고정 저항
- **LED(발광 다이오드)**: 한쪽 방향으로만 전류가 흐를 때 빛나는 반도체 소자
  - 극성 구분: 긴 다리 = **+ (애노드)**, 짧은 다리/평평한 쪽 = **− (캐소드)**
- **고정 저항**: 극성 없음(방향 무관). 색띠로 저항값 표시
  - **왜 필요한가**: LED가 감당할 수 있는 전류량이 정해져 있는데, 저항 없이 연결하면 과전류로 터짐. 저항이 전류를 제한해주는 역할 (실습에서는 220Ω 사용)
- 실습: 코인셀 3V 배터리 + 220Ω + LED

### 2-2. 스위치 — 디지털 ON/OFF
- **푸시 버튼**: 4핀 구조. 누르면 접점이 닫혀 연결, 떼면 열림 (순간 접촉)
- **슬라이드 스위치**: 3핀 — 가운데가 **공통 단자**, 양쪽이 선택 단자(L/R). 레버 위치에 따라 공통↔한쪽만 연결 (상태 유지 토글)

### 2-3. 가변저항 — 아날로그 연속 제어
- 0/1이 아닌 **연속적인 값**으로 저항을 조절
- 구조: 내부 저항체 + 회전 **와이퍼(wiper)**, 핀 3개
  - 1번 핀 기준: 와이퍼가 멀어질수록 저항 증가
  - 3번 핀 기준: 와이퍼가 가까울수록 저항 감소 (반대 방향)
- **물리 제어의 한계**: 사람이 직접 노브를 돌려야 함 → 코드로 자동 제어할 필요성 → MCU 등장

## 3. MCU와 아두이노 구조

### MCU (Micro Controller Unit)
- **하나의 반도체 칩 안에 컴퓨터 핵심 장치(CPU·메모리·입출력)가 모두 통합된 초소형 컴퓨터**
- 칩 자체를 MCU, 칩을 올린 보드를 MCU 보드라고 부름

### 대표 MCU 보드
| 보드 | 칩 | 특징 |
|---|---|---|
| 아두이노 UNO | ATmega328P | 입문용. WiFi/블루투스 없음 |
| **ESP32** | — | **WiFi + 블루투스 내장** (오프라인 실습에서 사용). 코드 작성 방식은 UNO와 거의 동일 |
| STM32 | — | 산업용 |
| RP2040 | — | 듀얼 코어 |

### 아두이노 UNO 핀
- **디지털 핀 (0~13)**: 0V 또는 5V, 즉 0/1만 다룸 (입출력 겸용)
- **아날로그 입력 핀 (A0~A5)**: 0~5V 전압을 0~1023 단계로 읽음
- **~ 표시가 있는 디지털 핀**: PWM 출력 지원 (3, 5, 6, 9, 10, 11번)
- 전원: 5V / 3.3V / GND

### 왜 C/C++인가
- **직접적 메모리 제어**: 하드웨어 접근 및 정밀 핀 통제
- **극한의 효율**: 2KB RAM 환경에서도 동작
- **실시간 반응**: 파이썬 대비 수십~수백 배 빠른 센서 응답
- C는 원래 운영체제를 만들기 위한 언어 → 임베디드 분야의 표준

### 프로그램의 뼈대 — 딱 두 함수
```cpp
void setup() {
  // [초기 설정] 전원이 켜지면 최초 1회만 실행
}

void loop() {
  // [무한 반복] setup 이후 계속 반복 실행
}
```

## 4. 아두이노 코드 정리

### 4-1. 내장 LED 깜빡이기 (Blink)
```cpp
void setup() {
  pinMode(LED_BUILTIN, OUTPUT);   // 내장 LED 핀을 "출력" 모드로 설정
}

void loop() {
  digitalWrite(LED_BUILTIN, HIGH); // 핀에 5V 출력 → LED 켜짐
  delay(1000);                     // 1000ms(1초) 대기
  digitalWrite(LED_BUILTIN, LOW);  // 핀에 0V 출력 → LED 꺼짐
  delay(1000);
}
```

**용어 정리**
| 용어 | 의미 |
|---|---|
| `pinMode(핀, 모드)` | 핀을 어떻게 쓸지 선언. `OUTPUT`(출력) / `INPUT`(입력) / `INPUT_PULLUP` |
| `digitalWrite(핀, 값)` | 디지털 출력. `HIGH`(5V) 또는 `LOW`(0V) |
| `delay(ms)` | 지정한 밀리초 동안 프로그램 정지 |
| `LED_BUILTIN` | 보드 내장 LED. UNO에서는 **13번 핀과 내부 연결**되어 있음 |

### 4-2. 외부 LED 제어
- 13번 핀 → 저항 → LED(+) → LED(−) → **GND(그라운드, −극)** 순으로 배선
- `LED_BUILTIN`이 13번과 연결되어 있으므로 코드는 4-1과 동일하게 동작

### 4-3. 버튼 입력 (INPUT_PULLUP)
```cpp
const int BUTTON_PIN = 2;
const int LED_PIN = 13;

void setup() {
  pinMode(BUTTON_PIN, INPUT_PULLUP); // 내부 풀업 저항 활성화 (플로팅 방지!)
  pinMode(LED_PIN, OUTPUT);
}

void loop() {
  int state = digitalRead(BUTTON_PIN); // 핀 상태 읽기 (HIGH/LOW)
  if (state == LOW) {                  // 풀업이므로 "눌림 = LOW" ← 주의!
    digitalWrite(LED_PIN, HIGH);
  } else {
    digitalWrite(LED_PIN, LOW);
  }
}
```

**용어 정리**
| 용어 | 의미 |
|---|---|
| `digitalRead(핀)` | 디지털 입력 핀의 상태를 읽음 → `HIGH` 또는 `LOW` |
| `INPUT_PULLUP` | 핀을 입력으로 쓰되, **MCU 내부 풀업 저항을 5V에 연결**해 기본 상태를 HIGH로 고정 |
| 논리 반전 | 풀업 방식에서는 **안 누름 = HIGH(1), 누름 = LOW(0)** |

→ 왜 이렇게 하는지는 [5. 플로팅 현상](#5-플로팅floating-현상-제대로-이해하기) 참고

### 4-4. 시리얼 통신 — PC와 대화하기
```cpp
void setup() {
  Serial.begin(9600);        // 통신 속도(baud rate) 9600으로 시리얼 시작
}

void loop() {
  int value = analogRead(A0); // A0 핀의 전압을 0~1023으로 읽기
  Serial.println(value);      // 값을 PC 시리얼 모니터로 출력 (줄바꿈 포함)
  delay(100);
}
```

**용어 정리**
| 용어 | 의미 |
|---|---|
| 시리얼 통신 | USB 케이블로 아두이노 ↔ PC 간 **양방향 데이터 이동** (전원 공급도 겸함) |
| `Serial.begin(속도)` | 통신 시작. PC 쪽 시리얼 모니터도 같은 속도여야 함 |
| `Serial.println(데이터)` | 데이터를 PC로 전송 + 줄바꿈. (`Serial.print`는 줄바꿈 없음) |
| `analogRead(핀)` | 아날로그 핀 전압(0~5V)을 **0~1023** 정수로 변환해 읽음 |
| 시리얼 모니터 | 아두이노가 보낸 텍스트를 보고, 반대로 입력도 보낼 수 있는 창. **디버깅의 기본 도구** |

### 4-5. 가변저항으로 LED 밝기 조절 (PWM + map)
```cpp
const int POT_PIN = A0;   // 가변저항 (250kΩ)
const int LED_PIN = 9;    // ~ 표시 있는 PWM 핀

void setup() {
  pinMode(LED_PIN, OUTPUT);
  Serial.begin(9600);
}

void loop() {
  int raw = analogRead(POT_PIN);          // 0 ~ 1023
  int brightness = map(raw, 0, 1023, 0, 255); // 범위 변환: 0~1023 → 0~255
  analogWrite(LED_PIN, brightness);       // PWM으로 밝기 출력
  Serial.println(brightness);
}
```

**용어 정리**
| 용어 | 의미 |
|---|---|
| `analogWrite(핀, 값)` | PWM 출력. 값은 **0~255** (0 = 항상 꺼짐, 255 = 항상 켜짐) |
| `map(값, 원래min, 원래max, 새min, 새max)` | 값의 범위를 다른 범위로 비례 변환. 입력(0~1023)과 출력(0~255)의 **사이즈를 일치**시킬 때 사용 |

→ PWM의 원리는 [6. PWM](#6-pwm-제대로-이해하기) 참고

### 4-6. 서보모터 제어
```cpp
#include <Servo.h>          // 서보 라이브러리 불러오기

Servo myServo;              // 서보 객체 생성

void setup() {
  myServo.attach(9);        // 서보 신호선을 9번 핀에 연결
}

void loop() {
  int raw = analogRead(A0);
  int angle = map(raw, 0, 1023, 0, 180); // 0~180도로 변환
  myServo.write(angle);     // 해당 각도로 회전
  delay(15);
}
```

**용어 정리**
| 용어 | 의미 |
|---|---|
| 서보모터 | DC모터가 "계속 도는" 것과 달리 **정확한 각도(보통 0~180°)로 위치를 제어**하는 모터. 위치 제어가 필요한 프로젝트의 대표 부품 |
| `#include <Servo.h>` | 서보 제어 함수가 들어있는 라이브러리를 가져옴 |
| `attach(핀)` / `write(각도)` | 신호 핀 지정 / 목표 각도 명령 |

### 4-7. CdS 조도 센서 — 전압 분배 회로
```cpp
const int CDS_PIN = A1;

void setup() {
  Serial.begin(9600);
}

void loop() {
  int light = analogRead(CDS_PIN); // 분배된 전압을 읽음
  Serial.println(light);           // 밝으면 큰 값, 어두우면 작은 값
  delay(200);
}
```

**핵심 개념 — 아두이노는 저항을 모른다**
- CdS 센서는 빛에 따라 **저항이 변하는** 부품 (밝으면 저항 ↓, 어두우면 저항 ↑)
- 그런데 아두이노 입력 핀은 **전압(0~5V)만 읽을 수 있고, 저항값은 직접 잴 수 없음**
- 그래서 저항 변화를 전압 변화로 바꿔주는 **전압 분배 회로**가 필요:

```
5V ──[CdS 센서]──●──[10kΩ 고정저항]── GND
                 │
               A1 핀 (측정점)
```

- 배선 3단계:
  1. **5V → CdS 센서** 한쪽 다리로 전기 인입
  2. **센서 반대쪽 다리 → A1 핀** (분배 전압 측정점)
  3. **A1 지점 → 10kΩ 저항 → GND** (전압 분배 기준점)
- 공식: `V_out = V_in × R2 / (R1 + R2)` — CdS 저항(R1)이 변하면 A1의 전압(V_out)이 변함
- 물에 비유: 유입(5V)과 배출(GND) 사이 중간 지점의 "수압"을 재는 것

### 4-8. 수동 부저 — tone()으로 멜로디
```cpp
const int BUZZER_PIN = 8;

void setup() {}

void loop() {
  tone(BUZZER_PIN, 262, 500); // 도(262Hz)를 500ms 동안
  delay(600);
  tone(BUZZER_PIN, 330, 500); // 미(330Hz)
  delay(600);
  tone(BUZZER_PIN, 392, 500); // 솔(392Hz)
  delay(600);
  noTone(BUZZER_PIN);         // 소리 즉시 중단
  delay(1000);
}
```

**용어 정리**
| 용어 | 의미 |
|---|---|
| `tone(핀, 주파수, 시간)` | 지정 핀으로 해당 주파수 소리를 지정 시간(ms) 동안 출력 |
| `tone(핀, 주파수)` | 시간 생략 시 **연속 발생** (noTone으로 꺼야 함) |
| `noTone(핀)` | 해당 핀 소리 출력 즉시 중단 |
| 주파수(Hz) | 공기가 1초 동안 진동하는 횟수. 높을수록 높은 소리 |
| 음계 주파수 | 도 262 / 레 294 / 미 330 / 솔 392 / 라 440 Hz |

### 4-9. RGB LED — 색 섞기
```cpp
const int R_PIN = 9;   // 모두 PWM(~) 핀
const int G_PIN = 10;
const int B_PIN = 11;

void setup() {
  pinMode(R_PIN, OUTPUT);
  pinMode(G_PIN, OUTPUT);
  pinMode(B_PIN, OUTPUT);
}

void setColor(int r, int g, int b) {  // 0~255로 색 지정하는 함수
  analogWrite(R_PIN, r);
  analogWrite(G_PIN, g);
  analogWrite(B_PIN, b);
}

void loop() {
  setColor(255, 0, 0);   delay(1000); // 빨강
  setColor(0, 255, 0);   delay(1000); // 초록
  setColor(255, 255, 0); delay(1000); // 노랑 (R+G)
  setColor(255, 255, 255); delay(1000); // 흰색 (R+G+B)
}
```
- RGB LED = 삼원색 소자가 하나로 통합된 다채색 램프
- **가장 긴 핀이 공통 단자** (실습 부품은 Common Cathode → GND에 연결)
- 각 색 핀을 PWM 핀(9, 10, 11)에 연결하면 색을 0~255 단계로 섞을 수 있음

## 5. 플로팅(Floating) 현상 제대로 이해하기

> 수업에서 "일단 INPUT_PULLUP으로 해결 가능하다"까지만 다룬 부분. 원리를 뜯어보자.

### 문제 상황
버튼을 입력 핀에 그냥 연결하면:
- 버튼을 **누르면** → 핀이 5V(또는 GND)에 연결되어 값이 확정됨 ✅
- 버튼을 **안 누르면** → 핀이 **아무 데도 연결되지 않은 상태**가 됨 ❌

이 "아무 데도 연결 안 된 상태"가 **플로팅(부유 상태)**:
- 5V도 GND도 아닌, 공중에 붕 떠 있는 불안정한 상태
- 핀에 연결된 전선이 **안테나처럼** 주변 전자기 노이즈를 흡수함
- 결과: 읽는 값이 0과 1 사이를 **무작위로 요동** → 버튼을 안 눌렀는데 눌렸다고 착각하는 오작동

### 왜 요동치는가 (직관)
디지털 입력 핀은 "지금 전압이 기준보다 높으면 1, 낮으면 0"으로 판정한다. 그런데 플로팅 핀의 전압은 정해준 사람이 없으니, 형광등·손·근처 전선이 만드는 미세한 전기장만으로도 기준선을 넘나든다. **"값이 없다"가 아니라 "값이 아무거나 된다"**는 게 핵심.

### 해결책: 기본값을 정해주자
안 눌렀을 때의 값을 **누군가 책임지고 정해주면** 된다. 그게 풀업/풀다운 저항.

**풀업(Pull-up)** — 핀을 저항을 통해 5V에 묶어둠:
```
5V ──[풀업 저항]──●── 입력 핀
                  │
               [버튼]
                  │
                 GND
```
- 버튼 안 누름: 핀이 저항을 통해 5V에 연결 → 항상 **HIGH(1)**
- 버튼 누름: 전류가 GND로 빠져나가 핀이 **LOW(0)**
- 저항이 있어서 누르는 순간 5V-GND 직결(합선)이 되지 않음

**INPUT_PULLUP** = 이 풀업 저항이 **MCU 칩 안에 이미 내장**되어 있어서, 외부 저항 없이 코드 한 줄로 활성화하는 것:
```cpp
pinMode(BUTTON_PIN, INPUT_PULLUP);
```

### 기억할 것
1. 입력 핀은 **반드시 기본 상태가 정의**되어야 한다 (플로팅 금지)
2. `INPUT_PULLUP` 사용 시 논리가 반전됨: **안 누름 = HIGH, 누름 = LOW**
3. 참고: 반대로 저항으로 GND에 묶는 **풀다운(Pull-down)**도 있음 (안 누름 = LOW). UNO는 내부 풀다운이 없어서 풀업을 주로 씀

## 6. PWM 제대로 이해하기

> "아날로그 값을 흉내낸다"의 정확한 의미.

### 문제 상황
- 디지털 핀은 **0V 아니면 5V, 딱 두 가지**만 출력 가능
- 그런데 LED 밝기 조절, 모터 속도 조절에는 2.5V 같은 **중간 값**이 필요
- 아두이노 UNO에는 진짜 아날로그 전압을 만드는 회로(DAC)가 없음

### 해결: 켜고 끄기를 아주 빠르게
**PWM(Pulse Width Modulation, 펄스 폭 변조)**: 전기를 켜고 끄는 **시간의 비율**을 조절해서 **평균 전압**을 바꾸는 기술.

```
duty 25%:  ▔▁▁▁▔▁▁▁▔▁▁▁   평균 ≈ 1.25V  (어두움)
duty 50%:  ▔▔▁▁▔▔▁▁▔▔▁▁   평균 ≈ 2.5V   (중간)
duty 75%:  ▔▔▔▁▔▔▔▁▔▔▔▁   평균 ≈ 3.75V  (밝음)
```

### 핵심 용어
| 용어 | 의미 |
|---|---|
| **듀티 사이클(Duty Cycle)** | 한 주기에서 **켜져 있는 시간의 비율(%)**. PWM의 실질적 조절 대상 |
| **주기/주파수** | 켜고 끄기를 반복하는 속도. UNO의 `analogWrite`는 약 490Hz(5·6번 핀은 980Hz)로, 1초에 수백 번 깜빡임 |
| `analogWrite(핀, 0~255)` | 0 = duty 0%, 127 ≈ 50%, 255 = 100%. **이름과 달리 진짜 아날로그가 아니라 PWM** |
| **~ 핀** | UNO에서 PWM을 지원하는 핀: 3, 5, 6, 9, 10, 11 |

### 왜 LED가 "어두워 보이는"가
- LED는 실제로 초당 수백 번 깜빡이고 있음
- 사람 눈은 그 속도를 못 따라가서 **평균 밝기**로 인식함 (잔상 효과)
- 모터의 경우: 관성 때문에 빠른 on/off가 **평균적인 힘**으로 작용 → 속도 조절

### 연결되는 개념들
- **서보모터**도 내부적으로 PWM 신호(펄스 폭)로 각도를 전달받음 — `Servo.h`가 그걸 대신 처리
- **`tone()`** 은 듀티는 고정하고 **주파수를 바꿔서** 소리 높낮이를 만듦 — 같은 "펄스" 계열이지만 조절 대상이 다름
- **RGB LED** 색 섞기 = 세 개의 채널 각각을 PWM으로 밝기 조절

### 입력과 출력 해상도가 다른 이유 (map을 쓰는 이유)
- `analogRead`: **10비트** ADC → 0~1023 (1024단계)
- `analogWrite`: **8비트** PWM → 0~255 (256단계)
- 서로 범위가 달라서 `map(raw, 0, 1023, 0, 255)`로 비례 변환이 필요

# 복습 심화 — 질문하며 잡은 개념들 (2026-08-05)

> 강의 정리 이후, 복습하며 직접 질문해서 잡은 개념들. 강의에는 없던 "왜?"에 대한 답.

## A. 저항값은 어떻게 정하는가 — 데이터시트 + 옴의 법칙

시뮬레이션 없이도 계산으로 안전한 저항값을 구할 수 있다.

1. **데이터시트(datasheet)**: 부품마다 제조사가 한계값을 문서로 공개함. 시뮬레이터의 "터진다" 경고도 이 값을 내장한 것
   - 빨간 LED 기준: 순방향 전압 V_f ≈ 2V (LED가 켜지며 떠안는 전압), 적정 전류 10~20mA, 최대 정격 ≈ 30mA
2. **계산 공식**: 남는 전압을 저항이 전부 떠안는다는 사실에서 출발

```
R = (전원 전압 − LED 순방향 전압) ÷ 목표 전류

예) 3V 코인셀 + 빨간 LED, 10mA 목표:
R = (3 − 2) / 0.01 = 100Ω  ← 실습 1에서 100Ω을 쓴 이유
예) 아두이노 5V + 빨간 LED, 15mA 목표:
R = (5 − 2) / 0.015 = 200Ω → 그래서 5V 회로의 국룰이 220Ω
```

3. **전원 전압이 바뀌면 저항값도 다시 계산** (ESP32는 3.3V!)
4. 시뮬레이션의 위치: 계산이 1차, 시뮬레이션은 계산 실수를 잡는 2차 검증

## B. 전압·전류·저항의 진짜 관계 — 역할 분담

| | 역할 | 비유 (수도) |
|---|---|---|
| **전압** | 미는 힘. 배터리가 정하고 우리는 못 바꿈 | 수압 |
| **전류** | 실제 흐르는 양. **부품을 죽이는 범인 = 관리 대상**. 그러나 직접 명령 불가 — 결과값 | 물의 양 |
| **저항** | 우리가 조절 가능한 유일한 손잡이 | 수도꼭지 |

핵심 문장: **전류는 "정해주는" 게 아니라 V와 R이 정해지면 "결과로 정해지는" 값** (I = V ÷ R). 그래서 저항을 골라 전류를 원하는 값으로 유도하는 것이 회로 설계의 기본 전략.

저항이 없으면 전류를 막는 것이 없어 폭주함 → "저항 없이 LED 직결 = 사망"의 진짜 의미.

## C. 전압을 "먹는다"는 것 — KVL (키르히호프 전압 법칙)

- **전류는 소모되지 않는다.** 회로 어디서나 같은 양이 흐르며 순환함 (물이 파이프를 지나며 사라지지 않듯)
- 소모되는 것은 **에너지**. 전압 = 전하가 가진 에너지의 높이
- 미끄럼틀 비유: 배터리 = 3m 계단(올림), LED = 2m 미끄럼틀(빛으로 방출), 저항 = 1m 미끄럼틀(열로 방출). 아이(전하)는 사라지지 않고 순환
- **한 바퀴 돌면 합은 정확히 0** (3V − 2V − 1V = 0). 출발점으로 돌아왔으니 높이도 원점 — 에너지 보존 법칙
- **인과관계 주의**: "LED가 2V를 먹는다"가 먼저가 아니라, **"합이 0이 되도록 자연이 전류를 조정한다"가 먼저**. 저항 없이 LED만 연결하면 남는 전압을 떠안을 부품이 없어 LED가 3V를 통째로 떠안고, LED 특성상 전압이 조금만 올라도 전류가 지수적으로 폭주 → 열로 사망
- 결론: 죽이는 건 전압이 아니라 **폭주한 전류(가 만든 열)**. 저항 = 남는 전압을 대신 떠안아 폭주를 막는 방패

## D. 가변저항 + 고정 저항을 같이 쓰는 이유 — 최소 저항 보장

- 가변저항은 노브를 끝까지 돌리면 **0Ω까지 내려갈 수 있음** → 그 순간 "저항 없이 직결"과 동일 = 전류 폭주
- 고정 저항 100Ω을 직렬로 깔면: 전체 저항 = 100Ω + (0~가변 최대값) → **바닥이 100Ω 밑으로 못 내려감** → 전류 천장 고정
- 비유: 가변저항 = 여닫는 수문, 고정 저항 = 수문이 다 열려도 남는 최후의 방파제
- 직렬 저항들은 전압을 저항값에 비례해 나눠 떠안음 → 같은 구조를 보호용으로 쓰면 "보호 저항", 측정용으로 쓰면 "전압 분배"(CdS 회로)

## E. 아날로그 vs 디지털 — 정의와 방향

- **디지털** = 값이 끊어진 계단으로만 존재 (0/1, 0~255 같은 정해진 단계)
- **아날로그** = 값이 끊김 없이 연속. **자연 세계는 원래 전부 아날로그**
- 가변저항은 "디지털→아날로그 변환"이 아니라 **처음부터 아날로그 원주민** (손 각도→저항→전류→밝기, 전부 연속)
- 디지털(MCU)이 아날로그 세계와 만나는 경계에 **번역기**가 필요:

```
아날로그 세계 ←→ [번역기] ←→ 디지털 세계(MCU)

읽기: 연속 전압 → analogRead(ADC) → 0~1023 계단값   (아날로그→디지털)
쓰기: 코드 0~255 → analogWrite(PWM) → 평균으로 흉내   (디지털→아날로그)
```

- 주의: `analogRead`의 0~1023도 엄밀히는 **1024단계의 디지털** (511.5는 없음). "아날로그를 읽어서 디지털로 바꾸는 함수"
- 한 줄 정리: **가변저항 = 아날로그 원주민, PWM = 디지털의 아날로그 흉내, analogRead/Write = 두 세계의 번역기**

## F. 보드 지도 — 다섯 구역

| 구역 | 위치 | 역할 |
|---|---|---|
| DIGITAL (PWM~) 0~13 | 위쪽 줄 | 0/1 입출력. ~핀(3,5,6,9,10,11)은 PWM 지원. 0(RX)/1(TX)은 시리얼 전용 — 시리얼 쓸 땐 부품 연결 금지 |
| ANALOG IN A0~A5 | 오른쪽 아래 | 연속 전압을 읽는 **입력 전용**. 아날로그 출력 전용 핀은 없음(비대칭) → 출력은 PWM이 대타 |
| POWER | 가운데 아래 | 부품 먹여 살리는 콘센트: 5V, 3.3V, GND×2, Vin(외부 전원 입력), RESET |
| 연결부 | 왼쪽 | USB(전원+코드 업로드+시리얼 3역할), 배럴 잭(7~12V 독립 전원, PC 없이 구동할 때) |
| 두뇌 | 한가운데 | ATmega328P 칩 = 진짜 MCU. 파란 보드는 이 칩의 받침대. L램프 = 13번(LED_BUILTIN), TX/RX 램프 = 통신 표시 |

- **3.3V 부품 쓰는 법**: POWER의 3.3V 핀 → 부품의 전원(VCC) 다리. 신호선은 별도로 디지털/아날로그 핀으로. (전원 구역과 신호 구역은 역할이 다름)
- **핀의 입력/출력**: 디지털 핀은 입과 귀를 둘 다 가진 방, 단 한 번에 한 역할. `pinMode(핀, OUTPUT/INPUT)`이 그 선언 — setup()에서 먼저 하는 이유

## G. 플로팅 심화 — "답을 정해주지 않은 질문"

- 아두이노는 입력 핀에 매 순간 "HIGH야 LOW야?"를 물음. 디지털 세계엔 "몰라"가 없어서 **무조건 0 아니면 1로 대답해야 함**
- 버튼이 안 눌린 순간 핀이 어디에도 연결 안 되어 있으면 = **밀어주는 힘(전압)의 공백** → 주변 노이즈(전자기기, 형광등, 손)에 따라 아무렇게나 대답 → 값이 0/1 사이 무작위 요동
- 해결 = **"안 눌렀을 때의 담당자"를 정하기**. 풀업 저항이 핀을 5V에 묶음 → 기본값 항상 HIGH, 누르면 GND로 빠져 LOW
- **프로그래밍 비유: 결측치(NaN)에 default 값 지정.** 풀업 = "이 핀의 default는 HIGH" 선언
- 눌러도 합선이 안 나는 이유: 경로에 풀업 저항(내부 약 20~50kΩ)이 끼어 있어 전류 = 5V ÷ 수십kΩ ≈ 0.1~0.25mA (방패 역할 그대로)
- 논리 반전의 기원: 기본값을 5V 쪽에 묶었으니 **눌림 = LOW** → `if (state == LOW)`
- INPUT_PULLUP = 외부에 달아야 할 풀업 저항이 칩 안에 내장되어 있어 코드 한 줄로 켜는 것 (부품 절약)
- **출력 핀은 플로팅 걱정 없음** — 값을 정하는 담당자가 MCU 자신이기 때문 (digitalWrite가 항상 5V나 0V로 밀어줌)

## H. PWM 심화 — 크기 대신 시간

- 한 문장 요약: **"0과 1은 크기 차이를 못 만드니, 켜져 있는 시간의 폭으로 차이를 만든다"** = Pulse Width Modulation
- 파형의 높이는 항상 5V로 동일. 다른 건 한 주기 내 켜진 구간의 폭 = **듀티 사이클** ("근무 시간 비율")
- **켜진 순간의 전류는 항상 최대치**: `analogWrite(핀, 127)`이어도 켜진 순간엔 (5−2)/220 ≈ 13mA 그대로 흐름. 13mA와 0mA를 시간 반반으로 섞어 **평균**만 절반으로 만드는 것. 눈과 모터 관성은 평균만 느낌

| | 가변저항 | PWM |
|---|---|---|
| 순간 전류 | 진짜로 줄어듦 | 항상 최대 아니면 0 |
| 어두운 이유 | 전류 크기가 작아서 | 꺼진 시간이 길어서 |
| 에너지 | 남는 전압이 저항에서 열로 버려짐 | 버리는 에너지 거의 없음 → **고효율. 실제 제품이 PWM을 쓰는 이유** |

- 개념 체인 완성: **전압=미는 힘 → 전류=결과이자 관리 대상 → 저항=크기를 줄이는 손잡이 → PWM=크기 대신 시간을 조절하는 손잡이**

## I. 서보모터와 진짜 아날로그 출력(DAC)

- **서보는 아날로그 값을 원하지 않는다.** 각도는 "펄스가 켜져 있는 시간의 길이"로 약속됨: 약 20ms 주기에서 1ms=0°, 1.5ms=90°, 2ms=180°
- 즉 서보가 원하는 건 정확한 타이밍의 디지털 펄스 = **디지털이 제일 잘하는 일**. `Servo.h`의 `write(90)`이 이 펄스 변환을 대행
- LED용 PWM과의 차이: LED는 "평균 전압"을 이용, 서보는 "펄스 폭 자체를 신호로 판독"
- **진짜 아날로그 출력 = DAC**(Digital-to-Analog Converter, ADC의 반대 방향 번역기)
  - UNO: DAC 없음 → PWM 흉내가 유일한 방법
  - **ESP32: DAC 핀 2개 내장** (0~3.3V를 256단계 진짜 전압으로)
- DAC가 필요한 경우: 오디오처럼 **파형 자체가 매끄러운 연속 전압**이어야 할 때. `tone()` 소리가 기계음인 이유 = 사인파가 아닌 각진 디지털 펄스라서
- 판단 기준: **평균만 맞으면 되는 출력(LED·모터·서보) → PWM 충분 / 파형이 연속이어야 하는 출력(오디오) → DAC 필요**

## J. RGB LED 핀 교정 메모

- 9, 10, 11번은 "아날로그 신호 핀"이 아니라 **PWM을 지원하는 디지털 핀(~)**. 각 색 채널의 켜진 시간 비율을 조절해 밝기를 섞는 것 (H의 원리 그대로 ×3채널)
- 색 = (R 듀티, G 듀티, B 듀티) 조합. 255,255,0 = 노랑, 255,255,255 = 흰색
- ⚠️ 공통 단자 주의: 수업 자료 텍스트는 Common Cathode(공통 −, GND 연결)라고 했는데 그림은 Common Anode(공통 +) 부품 그림이었음. **부품마다 다르므로 실물은 확인 필요** — Common Anode면 공통 핀을 5V에 연결하고 analogWrite 값의 논리가 반전됨(255=꺼짐)
